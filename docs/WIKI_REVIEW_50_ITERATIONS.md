# Wiki Generation Review - 50 Iterations

**Date:** 2025-12-08
**Model:** openai/gpt-4o-mini via OpenRouter
**Iterations:** 50 requested, 38 completed, 12 failed
**Total Cost:** $0.091
**Wiki Pages Created:** 71

## Executive Summary

After running CodeWiki for 50 iterations against its own repository, I identified **significant issues** that would compound if additional iterations were run. The wiki has fundamental problems with link generation, content duplication, and cross-referencing that should be addressed before further processing.

## Issues by Severity

### Critical Issues

#### 1. Broken Links - `.md` Extension Problem
**Impact:** 20+ internal links are broken
**Example:** Links in wiki pages include `.md` extensions that don't match actual page paths.

```markdown
# In agents/overview page:
[Orchestrator](agents/orchestrator.md)  # BROKEN - path is actually 'agents/orchestrator'
[Category Agent](agents/meta/category-agent.md)  # BROKEN
```

**Affected pages:** All pages generated by the `overview` agent that link to agent documentation.

**Root cause:** The overview agent generates links with `.md` extensions, but wiki page paths don't include extensions.

#### 2. Content Duplication - Same Topic, Multiple Pages
**Impact:** User confusion, wasted LLM tokens, inconsistent information
**Example:** LLM Service documented THREE times:

| Path | Title |
|------|-------|
| `services/llm` | "LLM Service Overview" |
| `services/llm-service` | "Language Model Service" |
| `components/llm-service` | "Llm Service" |

All three pages cover the same functionality with slight variations.

**Root cause:** Different agents (codebase-explorer vs code-change) are creating pages for the same content without deduplication checks.

#### 3. Missing Related Pages Section
**Impact:** Poor wiki navigation and discoverability
**Statistic:** 55 of 71 pages (77%) lack a "Related Pages" section

Pages without cross-references:
- All domain pages (4)
- All synthesis agent pages (11)
- All repository implementation pages (6)
- Most service pages (5)
- All guide pages (4)

**Root cause:** The link agent ran only 2 iterations out of 50, and was not applied to most pages.

### High Severity Issues

#### 4. Poor Commit Page Titles
**Impact:** Unreadable navigation, confusing page names
**Example:**
```
Title: "Merge pull request #238 from JKershaw/claude/add-openrouter-env-config-011cd1QjbHK9gPkqNhQLhb2B"
```

This is a full merge commit message used as a wiki page title instead of a descriptive summary.

**Root cause:** Code-change agent uses raw commit message as page title without summarization.

#### 5. Duplicate Page Titles
**Impact:** Ambiguous navigation
**Example:** Two pages titled "Auth":
- `web/public/modules/auth` - Frontend authentication module
- `web/routes/auth` - Backend authentication routes

#### 6. Inconsistent Title Capitalization
**Impact:** Unprofessional appearance
**Example:**
```
"test driven development (tdd) guidelines"  # all lowercase
"LLM Service Overview"  # Title case
```

### Medium Severity Issues

#### 7. High API Failure Rate
**Impact:** Incomplete wiki generation, wasted iterations
**Statistics:**
- 12 of 50 iterations failed (24%)
- All failures due to OpenRouter 503 errors

Agent failure breakdown:
| Agent | Total | Failed | Success Rate |
|-------|-------|--------|--------------|
| codebase-explorer | 32 | 8 | 75% |
| code-change | 7 | 3 | 57% |
| narrative | 1 | 1 | 0% |

**Root cause:** Transient network/TLS certificate errors from OpenRouter API. Retry logic (3 attempts) insufficient for sustained outages.

#### 8. Link Text Mismatch with Page Titles
**Impact:** Confusing navigation when link text doesn't match destination
**Example:**
```markdown
[Orchestrator for Code Documentation](agents/orchestrator)
# But page title is just "Orchestrator"
```

The link text embellishes the actual page title, creating inconsistency.

#### 9. Shallow Pages
**Impact:** Limited value to readers
**Statistics:** 20 pages with fewer than 16 lines of content

Examples of very short pages:
- `components/llm-service`: 10 lines
- `web/routes/config`: 12 lines
- `web/routes/filesystem`: 12 lines

### Low Severity Issues

#### 10. Agent Distribution Imbalance
**Observation:** Heavy reliance on codebase-explorer (64% of iterations)

| Agent | Iterations | Percentage |
|-------|------------|------------|
| codebase-explorer | 32 | 64% |
| code-change | 7 | 14% |
| link | 2 | 4% |
| Other | 9 | 18% |

The orchestrator is not effectively distributing work across agent types, leading to exploration-heavy wikis with poor linking and synthesis.

## Recommendations

### Immediate Fixes Required

1. **Fix link generation in overview agent** - Remove `.md` extensions from generated links
2. **Add deduplication check** - Before creating a page, check if similar content exists
3. **Improve commit page titles** - Generate descriptive titles from commit content, not raw messages

### Architecture Improvements

4. **Increase link agent priority** - Run link agent more frequently to improve cross-references
5. **Add title normalization** - Ensure consistent title casing
6. **Implement page consolidation** - Merge duplicate pages covering same topics

### Operational Improvements

7. **Better retry logic** - Implement exponential backoff with longer wait times for 503 errors
8. **Orchestrator rebalancing** - Reduce codebase-explorer dominance, increase synthesis agents

## Recommendation: Do Not Run Second Batch

Given the critical issues with link generation and content duplication, running additional iterations would:
1. Create more broken links
2. Generate more duplicate content
3. Waste API costs on flawed generation

**The identified issues should be fixed before running additional iterations.**

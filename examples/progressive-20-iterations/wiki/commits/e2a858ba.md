# Test Infrastructure and Organization

The CodeWiki project maintains a comprehensive test infrastructure organized into three distinct layers: unit tests, integration tests, and end-to-end tests. The test suite utilizes a centralized fixtures system that provides reusable mock factories for common testing scenarios, including mock LLM services, agent contexts, wiki pages, and commits. This fixture-based approach ensures consistency across tests and reduces duplication.

The testing architecture separates pure unit tests (which test isolated functions without mocking) from integration tests (which test component interactions with mocked dependencies). Test files are now organized by test type rather than collocated with source code, following a common convention where `tests/unit/` mirrors the `src/` structure and `tests/integration/` contains workflow and cross-component tests. The fixtures directory (`tests/fixtures/`) serves as a centralized repository for test utilities, exported through a single barrel file for convenient imports.

The mock infrastructure is particularly sophisticated for LLM testing, providing configurable mock services that can simulate different agent responses without making actual API calls. This includes specialized factory functions like `createCodeChangeMockLLM()`, `createLinkAgentMockLLM()`, and `createQualityAgentMockLLM()` that return pre-configured mocks with realistic agent-specific response patterns. These mocks track usage statistics, maintain request history, and support custom response handlers for testing complex scenarios.

## Key Findings

- **ARCHITECTURE** (high): Three-tier test organization (unit/integration/e2e) with dedicated fixture system providing reusable mocks and factories
- **TEST_PATTERN** (high): Mock LLM service with configurable response handlers, usage tracking, and specialized factory functions for different agent types
- **TEST_PATTERN** (medium): Centralized mock factories for AgentContext and WikiPage domain objects with sensible defaults and override support
- **CODE_ORGANIZATION** (medium): Test files moved from src/ directories to dedicated tests/ hierarchy, separating test code from production code
- **TEST_PATTERN** (medium): Vitest configuration updated to support the new test directory structure

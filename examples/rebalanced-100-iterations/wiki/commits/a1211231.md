# Orchestrator Rebalancing System

The Orchestrator Rebalancing System is a sophisticated work scheduling component that optimizes the order and bundling of AI agents to improve early wiki quality. The system operates through deterministic strategies that bundle multiple analysis agents per commit rather than processing commits sequentially by single agent types. This approach ensures comprehensive coverage of each code change before moving to the next, creating richer initial wiki content.

The rebalancing introduces several key improvements: analysis agents (code-change, narrative, security, technical-debt, pattern, dependency) are now bundled together per commit with code-change running first to establish base content, followed by specialized agents adding their perspectives. Meta agents (link, structure, quality, consistency) activate earlier - after processing 20+ commits or achieving 50% coverage rather than waiting for complete analysis. Synthesis agents (overview, project-overview, getting-started, writer) trigger at lower thresholds (8 pages instead of higher counts) to create structural documentation sooner. The system includes comprehensive testing infrastructure through mock LLM services and checkpoint tracking to validate that bundling works correctly, meta agents activate appropriately, and synthesis occurs at the right intervals.

The orchestrator maintains backward compatibility with optional LLM-powered decision making while defaulting to the improved deterministic strategies. Two utility scripts provide testing and demonstration capabilities: a test harness that validates rebalancing behavior with mock responses, and a wiki generation script that produces complete documentation with progress checkpoints and detailed analytics.

# Work Item Commit Reference System

The orchestrator's work item generation system uses Git commit SHA hashes as the primary identifier for targeting specific commits in the processing pipeline. This ensures consistent referencing across the multi-agent workflow where work items specify which commits should be processed by analysis agents.

The system maintains a clear separation between internal database identifiers (commit.id) and Git-native identifiers (commit.sha). Work items store the SHA hash in their targetCommitId field, which allows executors to reliably look up commits using Git's native addressing scheme. This design choice prevents mismatches that could occur if internal database IDs were used, since executors and other components expect to work with standard Git SHA references when interacting with repository data. The commit domain model supports this dual-identifier approach, storing both an internal UUID for database relationships and the Git SHA for external Git operations and work item targeting.

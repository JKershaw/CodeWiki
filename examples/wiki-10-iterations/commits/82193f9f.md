# Full Wiki Example: Multi-Agent Documentation System Demonstration

The full wiki example demonstrates a complete multi-agent documentation system processing 16 commits to generate 41 wiki pages across 9 specialized categories. This comprehensive example showcases the orchestration of 9 different agents working together: 5 analysis agents that process individual commits (code-change, narrative, security, pattern, dependency), and 4 meta-agents that enhance the wiki itself (link, structure, quality, consistency). The system processed commits with an average confidence of 56.1% and generated approximately $2.50 in LLM costs, demonstrating the practical economics and effectiveness of the approach.

The example illustrates how specialized agents create different documentation types from the same source material. Analysis agents generate commit-specific pages, architectural decision records (ADRs), security audits, coding standards, and dependency tracking. Meta-agents then enhance this content by adding cross-references between related pages, organizing the wiki structure, reviewing content quality, and identifying consistency issues. The result is a comprehensive, interconnected documentation system that captures not just what changed, but why decisions were made, what patterns emerged, and how components relate to each other.

The wiki structure demonstrates effective information architecture with 9 distinct categories: architecture (system design), commits (per-commit documentation), conventions (coding standards), decisions (ADRs), guides (how-to documentation), history (project timeline), patterns (design patterns and anti-patterns), planning (project management), and security (audit findings). This organization enables developers to find information through multiple pathways—whether searching by commit, by topic, or by architectural concern.

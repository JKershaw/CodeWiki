# CodeWiki Ignore File Support (.cwignore)

The CodeWiki system includes a `.cwignore` file mechanism that allows repositories to specify which files and directories should be excluded from analysis. This feature mirrors the familiar `.gitignore` syntax, providing developers with fine-grained control over what content gets processed by CodeWiki's analysis tools.

The cwignore service implements a robust pattern matching system using fast-glob and minimatch libraries. It supports standard glob patterns, directory exclusions (with automatic `/**` suffix addition), and comment syntax. The system includes built-in defaults that always exclude `node_modules/**` and `.git/**` directories, while allowing custom patterns to be layered on top through repository-specific `.cwignore` files.

The integration extends throughout the codebase tools, where file search, directory listing, and pattern matching operations all respect cwignore rules. A caching mechanism optimizes performance by storing parsed patterns per repository path, with explicit cache invalidation support for testing and dynamic updates. This ensures that CodeWiki analysis focuses only on relevant source code and documentation, avoiding generated files, dependencies, and other non-essential content.

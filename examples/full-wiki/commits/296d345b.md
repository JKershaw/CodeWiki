# Multi-Agent Processing Pipeline

The documentation automation system employs a multi-agent architecture where specialized agents analyze code commits from different perspectives to generate comprehensive wiki documentation. Five analysis agents work in coordinated sequence: the code-change agent establishes base documentation from general code analysis, followed by narrative, security, pattern, and dependency agents that add specialized perspectives on documentation artifacts, security implications, design patterns, and dependency management respectively.

The orchestrator manages this pipeline by generating work items for each commit-agent combination, ensuring every commit receives analysis from all five agents. This approach enables layered documentation where different aspects of changes are captured by agents with specialized prompts and expertise. For example, the narrative agent specifically identifies Architecture Decision Records (ADRs), planning documents, and README updates, while the security agent focuses on authentication, authorization, and security-relevant changes. Each commit tracks which agents have processed it via a `processedBy` array, enabling incremental processing where new agents can be added to analyze historical commits.

The system prioritizes recent commits (within the last week) over historical ones, and processes commits in chronological order with newest first. Coverage metrics are tracked per-agent, allowing visibility into which analytical perspectives have been applied across the codebase. This multi-agent approach produces richer, more comprehensive documentation than a single-agent system, as each specialized lens contributes unique insights about the same code changes.

# Commit 60a1d836

Add web interface and E2E tests

## Summary

This commit introduces a complete web interface for CodeWiki with an Express-based server and comprehensive E2E test suite using Playwright. The web interface provides three main views: repository management, wiki browsing, and natural language querying. The implementation includes a full REST API, static file serving, and a vanilla JavaScript frontend. Additionally, Playwright is configured specifically for containerized/sandboxed environments (like Claude Code on the web) with appropriate Chrome flags. A bug fix was also included in the file-based commit repository to handle both Date objects and ISO string dates from JSON deserialization.

## Findings

- **ARCHITECTURE** (high): Web tier added as new presentation layer with Express server, REST API, and static frontend, following a clear separation between API routes (/api/*) and static content. Includes repository management, wiki browsing, and query interfaces. src/web/server.ts, src/web/public/app.js, src/web/public/index.html
- **TESTING** (high): Comprehensive E2E test suite added using Playwright covering smoke tests, repository operations, query functionality, and wiki interactions. Tests run serially (workers: 1) to avoid resource contention. tests/e2e/smoke.spec.ts, tests/e2e/repositories.spec.ts, tests/e2e/query.spec.ts, tests/e2e/wiki.spec.ts, tests/e2e/api.spec.ts
- **INFRASTRUCTURE** (medium): Playwright configuration optimized for containerized environments with critical Chrome flags (--no-sandbox, --disable-setuid-sandbox, --single-process) to work in restricted environments like Claude Code on the web. playwright.config.ts
- **BUG_FIX** (medium): Fixed date handling in FileCommitRepository to support both Date objects and ISO string dates from JSON deserialization, which occurs when data is loaded from file storage. This is critical for proper sorting and filtering by date. src/repositories/file-based/file-commit-repository.ts
- **API_DESIGN** (high): RESTful API design with endpoints for repository CRUD operations (/api/repos), processing triggers (/api/repos/:id/process), wiki page access (/api/repos/:id/wiki), and natural language queries (/api/repos/:id/query). src/web/server.ts
- **UI_PATTERN** (medium): Single-page application (SPA) pattern with vanilla JavaScript, no framework dependencies. Uses view switching, state management, and fetch-based API communication. Manual DOM manipulation and event handling. src/web/public/app.js
- **SECURITY** (low): Basic HTML escaping implemented in frontend (escapeHtml function) to prevent XSS attacks, though server-side validation is not evident in the diff. src/web/public/app.js
- **UX** (medium): Polling mechanism implemented for long-running operations (repository processing) with 2-second intervals to provide status updates without WebSocket complexity. src/web/public/app.js
- **TECHNICAL_DEBT** (low): No framework used for frontend (vanilla JS) which may increase maintenance burden as complexity grows. Consider React/Vue/Svelte for future iterations. src/web/public/app.js
- **CONFIGURATION** (medium): Web server runs on configurable PORT (default 3001) with automatic startup via webServer config in Playwright, supporting both CI and local development scenarios. playwright.config.ts, package.json

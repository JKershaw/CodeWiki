# Web Interface and End-to-End Testing Infrastructure

CodeWiki provides a web-based interface for managing repositories, browsing generated wiki documentation, and querying the knowledge base. The interface is built as a single-page application (SPA) with vanilla JavaScript, offering three main views: repository management, wiki browsing, and natural language querying. The web server runs on Express.js and serves both the static frontend assets and the REST API endpoints.

The web interface architecture follows a clear separation between frontend and backend concerns. The server (src/web/server.ts) exposes REST API endpoints under `/api` for all repository and wiki operations, while serving static HTML, CSS, and JavaScript files from `src/web/public/`. The frontend maintains minimal state (current repository and page) and communicates with the backend through fetch requests, updating the UI dynamically based on API responses. This design allows the same backend services to be consumed by multiple interfaces—the CLI, MCP server, and now the web UI.

The testing infrastructure uses Playwright for end-to-end tests, with special configuration for containerized environments like Claude Code on the web. The configuration disables Chrome's sandbox and optimizes for single-process execution to avoid resource constraints in container environments. Tests are organized into separate spec files covering API functionality, query operations, repository management, and wiki generation, ensuring comprehensive coverage of the system's critical paths.

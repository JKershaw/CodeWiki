# Commit b908ecb1

Add project plan document

## Summary

This commit initializes the project by adding a comprehensive project plan document (PLAN.md). This is a foundational commit that establishes the vision, architecture, and technical approach for CodeWiki - a system that generates living documentation from Git repositories for AI coding agents. The plan outlines the core philosophy of eventual consistency over batch processing, describes a CQRS-based architecture with a two-loop orchestrator/executor model, and details the various specialized agents that will analyze commits and build the wiki. This appears to be a project inception document that will guide all subsequent development.

## Findings

- **ARCHITECTURE** (high): CQRS layer chosen as primary architectural boundary separating core system from external interfaces (HTTP, MCP, CLI). All interactions flow through commands and queries.
- **ARCHITECTURE** (high): Repository pattern with dual implementations (MongoDB for production, file-based for development/restricted environments) enabling flexible deployment scenarios.
- **ARCHITECTURE** (high): Two-loop model: lightweight orchestrator decides what work to do, executor runs agents in parallel. Write operations queued to prevent conflicts.
- **ARCHITECTURE** (high): Single writer agent pattern prevents race conditions - all wiki modifications flow through one component with conflict resolution.
- **PATTERN** (high): Confidence scoring system where every wiki entry includes confidence based on analysis depth, agent verification, and recency. Low-confidence areas prioritized for processing.
- **PATTERN** (medium): Multiple specialized analysis agents (Code Change, Narrative, Security, Technical Debt, Pattern, Dependency) each examining commits through different lenses.
- **PATTERN** (medium): Meta agents examine wiki structure itself (Structure, Link, Quality, Consistency) creating feedback loop for wiki improvement.
- **PATTERN** (medium): Synthesis agents create higher-order content (Guide, Overview, History, Convention) once sufficient raw material exists.
- **PHILOSOPHY** (high): "Eventual consistency over batch processing" - 80% wiki quickly beats 100% wiki slowly. Progressive enrichment model.
- **PHILOSOPHY** (medium): Self-documenting approach - CodeWiki will generate its own wiki using the system it builds.
- **TECHNICAL_DECISION** (medium): Node.js 20.4 runtime chosen (though document appears truncated).
- **TECHNICAL_DECISION** (medium): All state in single database (MongoDB), no external queue services - queues are database records with timestamps/status.
- **INTEGRATION** (high): MCP (Model Context Protocol) endpoint exposes research agent to external AI coding agents for querying context.
- **DATA_MODEL** (medium): Core collections defined: Repos, Commits, AgentRuns, WikiPages, WorkQueue, Conflicts, Learnings.
- **FEATURE** (medium): GitHub OAuth authentication for web interface, real-time progress visualization, throttle controls for cost management.

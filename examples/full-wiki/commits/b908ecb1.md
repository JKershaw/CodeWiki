# CodeWiki Project Architecture and Design Philosophy

CodeWiki is a system that generates living documentation from Git repositories by analyzing commit history and synthesizing institutional knowledge that traditional documentation rarely captures. Rather than simply documenting what code does, it captures the reasoning behind architectural decisions, failed approaches, subtle constraints, and evolving conventions—the institutional memory that AI coding agents need to work effectively on a codebase.

The system employs an eventual consistency model with a two-loop architecture: a lightweight orchestrator that continuously evaluates what work needs doing, and an executor that runs specialized analysis agents in parallel. All wiki modifications flow through a single write queue processed by a dedicated writer agent, preventing race conditions while multiple analysis agents examine commits through different lenses (code changes, security, technical debt, patterns, dependencies). The architecture follows CQRS principles with clean separation between commands/queries and the core domain logic, using a repository pattern that supports both MongoDB for production and file-based storage for restricted environments.

The design philosophy emphasizes eventual consistency over batch processing (producing a useful 80% wiki in 20 minutes rather than a perfect wiki in 10 hours), confidence scoring over completeness (every piece of information carries metadata about its reliability), and organic growth (the wiki progressively enriches itself by backfilling historical context). The system is architected for simplicity with all state in one database, no external queue services, and clean abstractions that make the codebase easy for AI agents to work on—particularly important since CodeWiki will generate its own documentation as a self-referential example.

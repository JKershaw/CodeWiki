# Browser Test Stability in Containerized Environments

The end-to-end test infrastructure uses Playwright to verify web application functionality in containerized environments like cloud development platforms. Browser stability in these constrained environments requires careful configuration of Chromium launch flags, particularly avoiding options that create tight coupling between browser contexts and the main browser process.

The `--single-process` flag, while seemingly appropriate for resource-constrained environments, creates a critical stability issue: when a browser context closes, the entire browser process terminates. This manifests as "Target page, context or browser has been closed" errors in tests that create and dispose of page contexts. Removing this flag and increasing timeout values from 30 to 60 seconds addresses the instability while maintaining compatibility with containerized execution.

Test assertions have been refined to handle asynchronous loading states more gracefully. Rather than checking for transient loading indicators that may disappear before assertions execute, tests now wait for stable end states (like the presence of content elements) or verify that meaningful content exists regardless of intermediate loading states. This approach reduces flakiness in environments with variable network and processing speeds.

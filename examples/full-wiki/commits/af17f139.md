# CQRS Architecture Implementation

CodeWiki is built on a Command Query Responsibility Segregation (CQRS) architecture, which cleanly separates operations that modify state (commands) from those that read state (queries). This architectural pattern provides a clear boundary between the core domain logic and external interfaces like HTTP APIs, CLI tools, or MCP servers.

The system organizes code into distinct layers: domain models that represent core business entities (repositories, commits, wiki pages, agent runs), commands that encapsulate all state-changing operations, queries that retrieve data without side effects, and repository interfaces that abstract data persistence. The repository layer uses a file-based implementation by default, storing data in JSON files under `.codewiki-data/`, though the interface-based design allows swapping in alternative storage backends like MongoDB without changing core logic.

This structure enables the system to maintain consistency and traceability for all state changes while keeping the domain logic independent of infrastructure concerns. Commands like `StartProcessingRepo` and `UpdateWikiPage` handle all mutations, returning standardized `CommandResult` objects that make success/failure handling uniform across all operations. The separation also makes the system more testable, as commands and queries can be tested independently of their delivery mechanism.

# Security Audit: Commit 84389967

**Relevance Level:** MEDIUM

## Summary

This commit introduces a Research Agent and MCP (Model Context Protocol) server for wiki querying functionality. The primary security concern is the addition of the `@modelcontextprotocol/sdk` dependency (v1.22.0) which brings in Express v5.1.0, CORS middleware, express-rate-limit, and various other dependencies. The code enables external querying capabilities through an MCP server, which introduces a new attack surface. Key security considerations include CORS configuration, rate limiting implementation, input validation for wiki queries, and the security posture of the dependency chain.

## Findings

### DEPENDENCIES (medium)

Addition of @modelcontextprotocol/sdk brings significant dependency tree including Express 5.x (major version upgrade from 4.x), CORS middleware, express-rate-limit, eventsource, and cross-spawn. This expands the attack surface and introduces potential for supply chain vulnerabilities. Express 5.x is a major version with breaking changes that need security review.

**Affected files:** `package.json`, `package-lock.json`

### CORS (medium)

The MCP SDK includes CORS middleware (v2.8.5) which if misconfigured could allow unauthorized cross-origin access to the wiki querying API. Default or overly permissive CORS settings could expose internal documentation to unauthorized domains.

**Affected files:** `node_modules/@modelcontextprotocol/sdk dependencies`

### RATE_LIMITING (low)

The inclusion of express-rate-limit (v7.5.0) suggests rate limiting is available but requires proper configuration. Without proper limits, the research agent could be subject to abuse or DoS attacks.

**Affected files:** `node_modules/@modelcontextprotocol/sdk dependencies`

### AUTHENTICATION (high)

The MCP server (src/mcp/server.ts) and Research Agent (src/agents/research/research-agent.ts) introduce new API endpoints for wiki querying. Without visibility into the actual implementation code, there's concern about whether proper authentication/authorization is enforced for these endpoints. Wiki documentation may contain sensitive internal information.

**Affected files:** `src/mcp/server.ts`, `src/agents/research/research-agent.ts`

### INPUT_VALIDATION (medium)

The Research Agent will process queries against wiki content. Without proper input validation, this could be vulnerable to injection attacks, path traversal (accessing unauthorized files), or query manipulation. The agent needs to validate and sanitize user queries.

**Affected files:** `src/agents/research/research-agent.ts`

### COMMAND_INJECTION (high)

The MCP SDK includes cross-spawn (v7.0.5), which is used for spawning child processes. If the MCP server or research agent uses this to execute commands based on user input without proper sanitization, it could lead to command injection vulnerabilities.

**Affected files:** `node_modules/@modelcontextprotocol/sdk dependencies`

### EVENT_SOURCES (low)

The inclusion of eventsource (v3.0.2) and eventsource-parser (v3.0.0) suggests SSE (Server-Sent Events) capabilities. If not properly secured, this could lead to information disclosure through event streams or resource exhaustion.

**Affected files:** `node_modules/@modelcontextprotocol/sdk dependencies`

### SCHEMA_VALIDATION (low)

The SDK includes ajv (v8.17.1) and zod (v3.23.8) for schema validation, which is positive for input validation. However, effectiveness depends on proper implementation in the actual agent code.

**Affected files:** `node_modules/@modelcontextprotocol/sdk dependencies`

## Potential Vulnerabilities

- [Information Disclosure] The Research Agent exposes wiki content through query capabilities. Without proper access controls, sensitive internal documentation could be exposed to unauthorized users or external parties. [CWE-200: Exposure of Sensitive Information]
- [Insufficient Authentication] New MCP server endpoints may lack authentication mechanisms, allowing anonymous access to internal wiki documentation. [CWE-306: Missing Authentication for Critical Function]
- [Command Injection Risk] If cross-spawn is used to execute git commands or other system operations based on user input, improper sanitization could lead to command injection. [CWE-78: OS Command Injection]
- [Path Traversal] If the research agent allows file path queries without proper validation, attackers could access files outside the intended wiki directory structure. [CWE-22: Path Traversal]
- [Cross-Site Scripting] If wiki content is returned without proper sanitization and includes user-generated content, XSS attacks could be possible. [CWE-79: Cross-site Scripting]
- [Denial of Service] Without proper rate limiting configuration, the MCP server could be overwhelmed with queries, causing resource exhaustion. [CWE-770: Allocation of Resources Without Limits]

## Recommendations

- Implement strong authentication and authorization for all MCP server endpoints. Consider using API keys, JWT tokens, or OAuth 2.0 depending on the use case.
- Configure CORS restrictively - only allow specific trusted origins rather than using wildcard (*) configurations. Document which domains should have access.
- Implement and configure express-rate-limit with appropriate thresholds to prevent abuse. Consider different limits for authenticated vs unauthenticated requests.
- Add comprehensive input validation for all query parameters. Use the included zod schemas to validate incoming requests and sanitize user input before processing.
- If using cross-spawn or executing any system commands, implement strict input sanitization and consider using allowlists for permitted operations. Never pass unsanitized user input to shell commands.
- Implement path validation to prevent directory traversal attacks. Use allowlists of permitted file paths or validate that requested paths are within the wiki directory.
- Add security headers (CSP, X-Frame-Options, X-Content-Type-Options) to HTTP responses from the MCP server.
- Implement comprehensive audit logging for all wiki queries including: user identity, query parameters, accessed content, timestamps, and IP addresses.
- Conduct a thorough security review of the actual implementation code in src/mcp/server.ts and src/agents/research/research-agent.ts (not visible in this diff).
- Consider implementing row-level security if the wiki contains content with different sensitivity levels - not all authenticated users should necessarily access all content.
- Review and document the security implications of upgrading from Express 4.x to 5.x, as this is a major version change with potential breaking changes.
- Set up dependency scanning (e.g., npm audit, Snyk, Dependabot) to monitor the new dependency tree for known vulnerabilities.

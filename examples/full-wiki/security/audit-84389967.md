# Security Audit: Commit 84389967

**Relevance Level:** MEDIUM

## Summary

This commit introduces a Research Agent and MCP (Model Context Protocol) server for wiki querying. The primary security concern is the addition of a significant new dependency (@modelcontextprotocol/sdk v1.22.0) which includes web server functionality (Express v5), request handling, authentication mechanisms (PKCE), CORS, and rate limiting. The MCP server likely exposes new attack surface for querying wiki content. Without seeing the implementation details in the truncated files (src/mcp/server.ts, src/agents/research/research-agent.ts), this introduces moderate security risk through expanded network exposure and dependency chain.

## Findings

### DEPENDENCY SECURITY (medium)

New MCP SDK dependency introduces substantial dependency tree including Express 5.1.0, CORS middleware, rate limiting, PKCE authentication, and request body parsing. This significantly expands the attack surface and introduces multiple security-critical components.

**Affected files:** `package.json`, `package-lock.json`

### AUTHENTICATION (medium)

MCP SDK includes PKCE (Proof Key for Code Exchange) challenge functionality, suggesting OAuth 2.0 authentication flows may be implemented. Without seeing the implementation, proper configuration is critical to prevent authorization bypass.

**Affected files:** `package-lock.json: pkce-challenge@5.0.0`

### NETWORK EXPOSURE (medium)

Express 5.1.0 server and CORS support indicate new HTTP endpoints being exposed. The server likely handles wiki queries, potentially exposing repository content and metadata to network requests. Implementation details needed to assess authorization controls.

**Affected files:** `src/mcp/server.ts`, `src/mcp/index.ts`

### INPUT VALIDATION (medium)

MCP SDK uses Zod (v3.23.8) and AJV (v8.17.1) for schema validation, which is positive for input validation. However, the research agent likely processes user queries against wiki content - these queries must be properly sanitized to prevent injection attacks.

**Affected files:** `package-lock.json`, `src/agents/research/research-agent.ts`

### RATE LIMITING (low)

Express-rate-limit (v7.5.0) is included, which is a security positive feature for DoS protection. Implementation details determine effectiveness.

**Affected files:** `package-lock.json`

### REQUEST PARSING (medium)

Raw-body parser (v3.0.2) and body-parser (v2.2.1) handle incoming request bodies. Improper size limits or parsing could lead to DoS or memory exhaustion attacks.

**Affected files:** `package-lock.json`

## Potential Vulnerabilities

- [Server-Side Request Forgery (SSRF)] If the research agent or MCP server allows querying arbitrary URLs or repository paths without proper validation, it could be exploited for SSRF attacks. [CWE-918]
- [Information Disclosure] Wiki querying functionality may expose sensitive repository content, commit messages, or internal documentation to unauthorized users if access controls are not properly implemented. [CWE-200]
- [Denial of Service] New server endpoints without proper rate limiting, request size limits, or query complexity controls could be exploited for DoS attacks. [CWE-400]
- [Injection Attacks] If wiki queries are not properly sanitized before processing against Git repositories or MongoDB, could lead to command injection or NoSQL injection. [CWE-74, CWE-89]
- [Cross-Origin Attacks] CORS middleware included but configuration not visible - misconfiguration could allow unauthorized cross-origin requests. [CWE-346]

## Recommendations

- Review and document the MCP server's authentication and authorization implementation, especially PKCE flow configuration if used
- Implement strict input validation on all wiki query parameters to prevent injection attacks
- Configure appropriate CORS policies with whitelist of allowed origins, avoid using wildcard (*)
- Set strict rate limits on query endpoints to prevent abuse and DoS
- Implement request size limits for body parsing to prevent memory exhaustion
- Add access control checks before returning wiki/repository content to ensure users can only query accessible repositories
- Conduct security review of exposed endpoints in src/mcp/server.ts once implementation is complete
- Add comprehensive audit logging for all wiki queries including user identity, query parameters, and results
- Review MCP SDK security advisories and keep dependency updated
- Implement query complexity limits to prevent resource-intensive operations
- Consider adding authentication requirements for wiki querying if not already present
- Use parameterized queries if accessing MongoDB or other data stores

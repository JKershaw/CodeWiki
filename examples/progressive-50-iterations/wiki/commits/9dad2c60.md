# Repository Ignore Patterns (.cwignore)

The .cwignore system provides a mechanism to exclude files and directories from CodeWiki's repository analysis. Similar to .gitignore syntax, it allows repository maintainers to prevent certain paths from being processed by the wiki generation system—particularly useful for excluding generated content, build artifacts, test fixtures, or any files that shouldn't contribute to documentation.

The system integrates seamlessly with the codebase exploration tools that agents use when analyzing commits. When an LLM agent uses tools like `search_files`, `list_directory`, or performs glob pattern matching, the ignore patterns are automatically applied. The implementation uses fast-glob for efficient pattern matching and includes sensible defaults (node_modules and .git directories) that are always ignored regardless of custom patterns.

Pattern caching ensures efficient performance across multiple tool invocations within the same repository analysis session. The cache is repository-specific, allowing different repositories to maintain their own ignore rules, and can be cleared programmatically when patterns change. The parser supports standard gitignore syntax including comments, glob patterns, and directory-specific rules (trailing slashes automatically expand to recursive patterns).

## Key Findings

- **FEATURE** (high): .cwignore file support added for filtering repository content from analysis
- **INTEGRATION** (high): Codebase tools now respect ignore patterns when searching/listing files
- **DEPENDENCY** (medium): Added fast-glob and minimatch libraries for pattern matching
- **ARCHITECTURE** (medium): Pattern caching implemented per repository for performance
- **TESTING** (high): Comprehensive unit tests cover pattern parsing and file loading
- **TESTING** (medium): Integration tests updated to clear ignore cache between test runs
- **DEFAULT** (medium): node_modules and .git always excluded by default regardless of .cwignore
- **SYNTAX** (low): Directory patterns ending with / automatically expand to /** for recursive matching
- **LIMITATION** (low): Negation patterns (starting with !) are not supported and are silently ignored

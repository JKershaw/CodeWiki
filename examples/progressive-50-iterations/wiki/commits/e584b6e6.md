# Orchestrator and Executor Communication Protocol

The orchestrator and executor components use different identifier schemes when communicating about Git commits. The orchestrator generates work items using Git SHA hashes (e.g., "a1b2c3d..."), which are the standard cryptographic identifiers that Git uses to reference commits. However, the executor expects internal UUID identifiers that the system assigns to commits when they are imported into the database.

This architectural decision creates a clear separation of concerns: the orchestrator operates at the Git abstraction level, dealing with commits as they exist in the repository, while the executor operates at the domain model level, dealing with commits as first-class entities in the application. The executor performs the translation by looking up commits using `findBySha()` to convert Git SHAs into internal UUIDs before executing agent runs. This translation happens in the `executeWorkItem()` method, ensuring that agents always receive consistent internal identifiers.

The work item domain model supports both identifier types through its `targetCommitId` field, which can hold either a SHA or UUID depending on where in the pipeline it's being used. The commit domain model maintains both identifiers (`sha` for Git compatibility and `id` for internal references), allowing seamless translation between the two systems. This design enables the orchestrator to make decisions based on Git-native concepts while the executor maintains referential integrity within the application's data model.

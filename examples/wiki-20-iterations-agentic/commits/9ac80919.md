# Agentic Tool Use for Code Analysis

The Code Change Agent employs an agentic architecture that enables the LLM to autonomously explore the codebase beyond the limited context provided by git diffs. Through an iterative tool-use loop, the agent can read complete source files, search for related test files, and understand project structure before generating documentation. This approach transforms the agent from a passive diff analyzer into an active code explorer.

The system provides three codebase exploration tools: `read_file` for accessing full file contents (with security validation and size limits), `search_files` for glob-pattern-based file discovery, and `list_directory` for understanding project organization. The agent can make up to 5 rounds of tool calls, allowing it to build comprehensive context incrementally—for example, reading a changed file to see the complete implementation, then searching for its test files, then examining imported dependencies.

This agentic capability significantly improves documentation quality and confidence. Instead of guessing about implementation details from partial diffs, the agent can verify assumptions by reading source code directly. The system tracks tool usage as low-importance findings, creating transparency about which files were examined during analysis. This architectural pattern—equipping agents with tools for autonomous exploration—establishes a foundation that can be extended to other analysis agents (pattern recognition, security auditing, etc.) as they mature beyond simple prompt-response interactions.

# Agentic Tool Use System

CodeWiki agents are augmented with tool-using capabilities that allow them to explore the codebase during their reasoning process. Previously, agents operated "blind"—they could only see commit diffs and existing wiki pages, leading to poor quality outputs like "project purpose cannot be determined" even when README.md clearly explained the project. The tool use system follows Anthropic's recommended patterns for building effective agents, implementing an agentic loop where the LLM can iteratively gather context, take actions, and verify work.

The architecture introduces three core tools: `read_file` for reading complete file contents, `search_files` for finding files by glob pattern, and `list_directory` for understanding project structure. These tools are integrated through a new `completeWithTools` method in the LLM service that orchestrates multi-round conversations where the agent can make tool calls, receive results, and iterate up to a configurable limit (default 5 rounds). The implementation includes safety measures like path sandboxing to prevent traversal attacks, file size limits to control costs, and round limits to prevent infinite loops.

The project-overview agent serves as the first implementation, using tools to read README.md, package.json, and other documentation files before synthesizing a comprehensive overview. This represents a fundamental architectural shift from single-shot prompt-response patterns to iterative, context-gathering workflows. The system maintains the existing CQRS and repository patterns while extending the agent context to include physical repository paths and tool definitions. Cost tracking has been enhanced to aggregate token usage across all tool rounds, and test coverage includes unit tests for individual tools, integration tests for the tool execution loop, and safety validations for path traversal and file size limits.

## Key Findings

- **ARCHITECTURE** (high): Implementation of agentic tool use pattern following Anthropic best practices for augmented LLMs with iterative context gathering, tool execution, and multi-round conversations
- **CAPABILITY** (high): Three core codebase exploration tools: read_file for reading complete files, search_files for glob pattern matching, and list_directory for understanding project structure with path sandboxing and file size limits
- **API** (high): New completeWithTools method in LLM service interface supporting tool definitions, tool execution callbacks, configurable round limits, and aggregated token/cost tracking across multi-round conversations
- **ENHANCEMENT** (high): Project overview agent upgraded to use tools for reading source files (README.md, package.json, PLAN.md) before synthesizing documentation, dramatically improving output quality from generic guesses to actual project information
- **PATTERN** (medium): Tool execution loop implements Anthropic SDK pattern: LLM requests tools → executor runs them in parallel → results fed back as messages → repeat until end_turn or max rounds, with final forced text output if rounds exhausted
- **SECURITY** (high): Path validation prevents traversal attacks by resolving paths and verifying they remain within repository root, file size limits prevent runaway costs, and tool round limits prevent infinite loops
- **TESTING** (medium): Comprehensive test coverage including temporary directory setup, tool execution validation, security tests for path traversal, and file size limit enforcement
- **DESIGN** (medium): Non-breaking migration strategy: completeWithTools added alongside existing complete method, agents opt-in to tool use, gradual rollout planned starting with highest-impact synthesis agents
- **INTEGRATION** (medium): Agent context extended to include repoPath for physical filesystem access and tools array for available tool definitions, enabling tools while maintaining existing architecture patterns
- **OBSERVABILITY** (medium): Tool usage tracked in agent findings showing number of tool calls and files read, cost tracking aggregates across all rounds, and tool call details captured in ToolUseResult for debugging and analysis

# Page-Count Based Synthesis Triggers for Wiki Quality

The orchestration system now uses page-count thresholds instead of percentage-based coverage to trigger synthesis work, ensuring that even large repositories (1000+ commits) receive useful high-level documentation early in the processing cycle. This change addresses a critical usability issue where wikis remained commit-focused for too long before generating project overviews, getting started guides, and other synthesis content that helps developers understand the codebase.

The new thresholding system operates on fixed page counts: synthesis begins after 5 pages (20% of iterations), increases priority at 10 pages (30% of iterations), and requires project overview and getting started documentation at 15+ pages. This replaces the previous 60% coverage threshold which, for repositories with hundreds of commits, meant waiting through hundreds of iterations before synthesis agents ran. The system also distinguishes between Git commit SHAs (used in orchestrator decisions) and internal UUIDs (used by executors), fixing a mismatch that caused orchestrator decisions to reference the wrong commit identifiers.

Complementing these orchestration changes, the wiki export system now generates more useful index pages. Instead of simply listing pages, the index extracts project descriptions from overview pages, displays quick-start links prominently, and collapses commit documentation into a summary section. This transforms the index from a table of contents into an actual introduction to the project, making the wiki immediately useful for AI coding agents and human developers who need to understand a codebase quickly.

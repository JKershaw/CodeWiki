# CLI Simplification and Wiki Iteration Examples

The command-line interface now exclusively uses LLM-powered orchestration for intelligent decision-making about what work to perform on the wiki. This simplification removes the previous deterministic mode option, standardizing on AI-driven prioritization that adapts to the wiki's current state rather than following fixed rules. The orchestrator analyzes commit coverage, page quality, and other metrics to generate ranked work items, ensuring the system focuses on the most valuable improvements at each step.

A comprehensive set of iteration examples demonstrates how wiki quality evolves as the orchestrator processes different numbers of commits. These examples show progression snapshots at 1, 2, 5, 10, and 20 iterations, capturing both the raw wiki pages and the underlying JSON data structures. Each example includes individual commit analyses, synthesized overview pages, and architectural documentation that emerges as agents identify patterns across the codebase. A comparison document analyzes how page count, confidence scores, and content organization improve as more iterations complete, providing empirical evidence of the system's effectiveness.

The context-gathering system provides the orchestrator with comprehensive wiki state information including which commits have been analyzed by which agents, category statistics, page quality indicators, and recent activity patterns. This rich context enables the LLM to make informed decisions about whether to analyze new commits, generate category overviews, improve page quality, or skip work when the wiki is already in good condition.

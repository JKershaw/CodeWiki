# Wiki Quality Orchestration System

The wiki generation system uses a page-count based orchestration strategy to ensure documentation quality and usefulness for AI coding agents. Rather than generating hundreds of commit-focused pages before synthesizing higher-level documentation, the orchestrator now triggers synthesis work early based on absolute page counts (5, 10, and 15 pages) instead of repository coverage percentages.

The orchestration logic prioritizes what makes wikis useful: project overviews, architecture explanations, and well-structured navigation over exhaustive commit-by-commit coverage. For a 1000-commit repository, the old percentage-based approach (60% coverage threshold) would generate 600 pages before creating an overview, while the new system creates structural documentation after just 15 pages. This reflects a key insight that "a useful wiki with good structure beats comprehensive coverage" - AI agents need to understand projects quickly, not read every commit sequentially.

The wiki index has been redesigned to function as a true landing page rather than a flat list. It extracts the project description from overview pages, provides prominent quick-start links, and collapses the commits section into a summary. High-confidence pages in categories like decisions and patterns are surfaced prominently, making the wiki immediately useful for developers trying to understand "what this system is" rather than "what changed in commit X."

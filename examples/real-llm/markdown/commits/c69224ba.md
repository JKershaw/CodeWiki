# Commit c69224ba

Add core processing pipeline with CLI

## Summary

This commit establishes the core processing pipeline for CodeWiki, implementing a complete agent-based architecture for analyzing Git commits and generating wiki documentation. It introduces a CLI interface, an orchestrator pattern for managing multiple analysis agents, the first concrete agent (CodeChangeAgent) for commit analysis, service abstractions for Git and LLM operations, and an executor system for applying wiki updates. The architecture follows a clean separation of concerns with agents, services, executors, and a command-line interface for repository analysis.

## Findings

- **ARCHITECTURE** (high): Implements multi-agent orchestration pattern with base agent abstraction, allowing different analysis perspectives on the same commits
- **DESIGN_PATTERN** (high): Uses dependency injection through AgentContext for testability and flexibility, passing repositories, services, and config to agents
- **LLM_INTEGRATION** (high): Abstracts LLM interactions with cost tracking and includes mock implementation for testing, showing production readiness
- **SELF_DOCUMENTING** (high): The CodeChangeAgent uses structured prompts to parse its own output format, creating a self-referential documentation system
- **CLI** (medium): Adds executable CLI with bin configuration, making the tool installable and usable as a command-line utility
- **GIT_INTEGRATION** (medium): Implements Git service abstraction for repository operations and diff retrieval, enabling version control integration
- **EXECUTION_MODEL** (medium): Separates analysis (agents) from application (executor), allowing for review/approval workflows before wiki updates
- **WIKI_UPDATE_TYPES** (medium): Supports create/update/merge operations with confidence tracking, enabling iterative documentation refinement
- **PROMPT_ENGINEERING** (medium): Uses structured prompt format with clear sections and formatting instructions for reliable LLM parsing
- **TECHNICAL_DEBT** (low): Diff truncation at 10KB may lose context for large commits, could implement smart truncation strategies
- **TECHNICAL_DEBT** (low): Regex-based response parsing is brittle; consider JSON output format from LLM for more reliable parsing

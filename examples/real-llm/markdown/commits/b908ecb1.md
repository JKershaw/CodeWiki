# Commit b908ecb1

Add project plan document

## Summary

This commit establishes the foundational project plan for CodeWiki, a system that generates living documentation from Git repositories by analyzing commit history. The plan defines a comprehensive architecture using CQRS pattern, repository abstraction, and an orchestrator-agent model. Key philosophical decisions include eventual consistency over batch processing, confidence scoring for all content, organic wiki growth, and simplicity in architecture. The system is designed to be consumed by AI coding agents via MCP (Model Context Protocol) to provide contextual understanding of codebases.

## Findings

- **ARCHITECTURAL_DECISION** (high): CQRS layer chosen as the primary boundary between core logic and external interfaces (commands for writes, queries for reads), enabling clean separation of concerns and multiple client types (HTTP, MCP, CLI).
- **ARCHITECTURAL_DECISION** (high): Repository pattern with dual implementations (MongoDB for production, file-based for local/restricted environments) enables deployment flexibility and testing isolation.
- **ARCHITECTURAL_DECISION** (high): Two-loop orchestration model: lightweight outer loop (Orchestrator) makes prioritization decisions, inner loop (Executor) executes work with parallelism. This separates "what to do" from "doing it".
- **ARCHITECTURAL_DECISION** (high): Single-writer pattern via write queue prevents race conditions and enables conflict resolution, with all wiki modifications funneled through one Writer Agent.
- **DESIGN_PHILOSOPHY** (high): Eventual consistency preferred over completeness - aims for "80% wiki in 20 minutes" rather than "100% wiki in 10 hours", prioritizing usefulness over exhaustiveness.
- **DESIGN_PHILOSOPHY** (medium): Confidence scoring on all wiki content based on commit coverage, agent verification, and recency enables calibrated trust and prioritization.
- **TECHNICAL_DECISION** (medium): All state in single database, queues as database records rather than external services, prioritizing simplicity and debuggability over distributed complexity.
- **INTEGRATION** (high): MCP (Model Context Protocol) endpoint exposes wiki knowledge to AI coding agents, enabling them to query for context before starting work.
- **AGENT_ARCHITECTURE** (high): Multi-agent system with specialized agents: Code Change, Narrative, Security, Technical Debt, Pattern, Dependency for analysis; Writer for modifications; Research for querying; Meta agents for wiki quality; Synthesis agents for higher-order content.
- **TECHNICAL_DECISION** (medium): Node.js 20.4 chosen as runtime, TypeScript for implementation, Anthropic Claude as LLM, MongoDB as primary datastore.
- **WORKFLOW** (medium): OAuth-based GitHub integration for repository access, with webhook support for real-time commit processing.
- **META_STRATEGY** (medium): Self-hosting approach - CodeWiki will generate its own wiki as a demonstration and validation of the system.
- **FEEDBACK_LOOP** (medium): Learnings from AI coding sessions (mistakes, missed conventions) ingested back into wiki to improve future agent performance.

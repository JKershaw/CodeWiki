# Security Audit: Commit 84389967

**Relevance Level:** MEDIUM

## Summary

This commit introduces a Research Agent and MCP (Model Context Protocol) server for wiki querying functionality. The primary security concern is the addition of the `@modelcontextprotocol/sdk` dependency (v1.22.0) which brings in multiple sub-dependencies including Express 5.1.0, CORS support, rate limiting, and PKCE authentication flow capabilities. The MCP server appears to provide an API interface for querying wiki content. Without seeing the actual implementation code in the diff (truncated), the security assessment focuses on the dependency chain and architectural implications.

## Findings

### DEPENDENCIES (medium)

The MCP SDK introduces significant dependency surface area including express@5.1.0, cors@2.8.5, express-rate-limit@7.5.0, eventsource, raw-body parsing, and PKCE authentication flow (pkce-challenge@5.0.0). These dependencies handle security-sensitive operations including HTTP request parsing, CORS policy enforcement, rate limiting, and OAuth PKCE flows. The implementation quality of these handlers will determine actual security posture.

**Affected files:** `package.json`, `package-lock.json`

### AUTHENTICATION (medium)

The pkce-challenge dependency suggests OAuth 2.0 with PKCE (Proof Key for Code Exchange) authentication may be implemented. PKCE is a security extension for OAuth that prevents authorization code interception attacks. Without seeing the implementation, cannot verify if properly configured.

**Affected files:** `package.json dependencies`

### INPUT_VALIDATION (medium)

The SDK includes ajv@8.17.1, ajv-formats@3.0.1, zod@3.23.8, and json-schema validation. These are positive security controls for input validation, but effectiveness depends on implementation. The raw-body@3.0.0 parser requires careful handling to prevent DoS via large payloads.

**Affected files:** `package-lock.json`

### CORS (medium)

CORS@2.8.5 is included, which if misconfigured could allow unauthorized cross-origin access to the MCP API endpoints. Default permissive CORS settings would be a security issue.

**Affected files:** `package-lock.json`

### RATE_LIMITING (low)

Express-rate-limit@7.5.0 provides DoS protection, which is a positive security control if properly configured.

**Affected files:** `package-lock.json`

### TRANSPORT_SECURITY (low)

The eventsource@3.0.2 and eventsource-parser@3.0.0 dependencies suggest Server-Sent Events (SSE) may be used for real-time updates. SSE over HTTP (not HTTPS) could expose data in transit.

**Affected files:** `package-lock.json`

## Potential Vulnerabilities

- [Information Disclosure] Without seeing the actual MCP server implementation (src/mcp/server.ts truncated in diff), potential risks include exposing sensitive wiki content without proper authorization checks, or leaking system information through error messages.
- [Authorization Bypass] The research agent querying functionality could potentially allow unauthorized access to private or sensitive documentation if role-based access controls are not properly implemented in the MCP server endpoints.
- [Denial of Service] Express body parsers (body-parser@2.2.1, raw-body@3.0.2) need payload size limits configured to prevent memory exhaustion attacks. The raw-body dependency shows it uses bytes and http-errors, suggesting some protection, but configuration is critical.
- [Dependency Vulnerabilities] The large dependency tree (368+ lines of new dependencies) increases attack surface. Notable that express@5.1.0 is a major version upgrade which may have breaking changes affecting security configurations from express@4.18.2 already in project.

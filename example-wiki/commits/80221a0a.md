# Agentic Tool-Using Architecture

The CodeWiki system implements an agentic architecture that enables AI agents to explore codebases using tools, following Anthropic's recommended patterns for building effective agents. This design addresses a critical limitation where agents were previously "blind" to repository context—they could only see commit diffs and existing wiki pages, leading to poor quality output even when relevant documentation like README.md existed in the repository.

The architecture introduces a tool-based system where agents can read files, search content, list directories, and explore the codebase structure during their analysis. This follows the "augmented LLM" pattern from Anthropic's research, combining language models with retrieval capabilities and memory. The implementation uses a loop-based approach where agents iteratively gather context, take actions through tools, verify their work, and repeat until they have sufficient information to generate high-quality documentation.

The design emphasizes starting simple and adding complexity only when needed, with careful attention to tool design, security sandboxing, and resource limits. Tools are defined using Zod schemas for type safety and validation, and the system supports both sequential and parallel tool execution depending on whether operations are independent.

## Key Findings

- **ARCHITECTURE** (high): Agentic tool-using pattern enables agents to explore codebases iteratively rather than working with limited diff context. AGENTIC_TOOLS_PLAN.md
- **DESIGN** (high): Tool definitions use Zod schemas for input validation with JSON Schema conversion for Anthropic API compatibility. AGENTIC_TOOLS_PLAN.md
- **INTERFACE** (high): New completeWithTools method extends LLM service with tool loop orchestration, supporting up to 5 rounds of tool calls by default. AGENTIC_TOOLS_PLAN.md
- **TOOLS** (high): Four core codebase exploration tools planned: read_file, search_files, search_content, list_directory. AGENTIC_TOOLS_PLAN.md
- **SECURITY** (high): Path sandboxing prevents directory traversal attacks and limits file access to repository boundaries. AGENTIC_TOOLS_PLAN.md
- **PATTERN** (medium): Tool execution loop follows assistant response → tool calls → tool results → repeat pattern until completion or max rounds. AGENTIC_TOOLS_PLAN.md
- **INTEGRATION** (medium): Project overview and getting started agents upgraded to use tools for reading README.md, package.json, and exploring directory structure. AGENTIC_TOOLS_PLAN.md
- **LIMITS** (medium): Resource constraints include file size limits (1MB), token budgets per tool call (10k tokens), and sandbox restrictions. AGENTIC_TOOLS_PLAN.md
- **OBSERVABILITY** (medium): Tool usage tracking via Prometheus metrics enables monitoring of call counts, latencies, and token consumption. AGENTIC_TOOLS_PLAN.md
- **TESTING** (medium): Three-tier testing strategy covers tool execution, agent behavior, and integration scenarios with mock repositories. AGENTIC_TOOLS_PLAN.md

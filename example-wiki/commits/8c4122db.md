# CLI Architecture and Wiki Progression Examples

The command-line interface uses LLM-powered orchestration as its default and only mode of operation, eliminating the earlier dual-mode design that offered both deterministic rule-based and AI-powered work prioritization. This architectural simplification reflects the project's commitment to intelligent, context-aware decision-making throughout the documentation generation pipeline. The CLI provides commands for processing commits, running orchestrated work sessions, and generating complete wiki documentation from Git repositories.

The system includes comprehensive progression examples that demonstrate how wiki documentation evolves through iterative processing. These examples show snapshots of wiki states after 1, 5, 10, and 20 orchestration iterations, illustrating how content quality improves, pages become more interconnected, and higher-order synthesis documentation (like category overviews and architectural guides) emerges from accumulated commit-level analysis. Each progression example includes the full wiki state, commit-specific pages, and index pages that track coverage and confidence metrics.

The progression examples serve multiple purposes: they validate the orchestration system's effectiveness, provide regression testing data, document expected system behavior, and help developers understand how the multi-agent pipeline transforms raw commit data into comprehensive project documentation. The examples reveal patterns like initial sparse coverage converging toward comprehensive documentation, confidence scores stabilizing as agents cross-validate findings, and structural improvements (linking, categorization, overview generation) occurring after sufficient content accumulation.

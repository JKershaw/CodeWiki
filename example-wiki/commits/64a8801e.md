# Orchestration Strategy: Page-Count Based Synthesis Triggers

The orchestrator uses a page-count based strategy to determine when to trigger synthesis and meta-analysis work on the wiki. This approach ensures that structural improvements and high-level documentation are created early in the wiki generation process, rather than waiting until most commits have been processed. The system operates on three thresholds: after 5 pages, synthesis work begins at 20% frequency; after 10 pages, it increases to 30%; and after 15 pages, critical overview documentation is prioritized if missing.

This strategy addresses a fundamental problem with percentage-based triggers: in large repositories with thousands of commits, waiting for 60% coverage would mean hundreds of iterations before creating overview documentation. For AI coding agents consuming the wiki, having a well-structured wiki with good architectural overview at 10% coverage is far more useful than having comprehensive commit documentation at 60% coverage with no structural guidance. The system treats the wiki as an encyclopedia for developers, not a commit changelog.

The implementation spans several components: the orchestrator decision logic, context gathering for recent commits (now using Git SHAs instead of internal UUIDs), and wiki export improvements that present synthesized content prominently while de-emphasizing individual commit pages. The index page generation has been redesigned to extract project descriptions from overview pages and collapse commit listings into a summary section, ensuring the wiki reads as documentation rather than a commit feed.
